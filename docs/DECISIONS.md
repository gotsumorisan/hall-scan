# 仕様の解釈と不足情報

1. 添付starter promptは「新規リポジトリ・まずからくり2のみ」。最上位handoffの既存repo承認待ち手順は変更対象がある場合の指示と解釈。初期フォルダに既存コードがないため、監査結果を記録して新規作成した。10機種完了条件は後続段階とし、今回の明示範囲1機種に従った。
2. handoffには正式A候補ラインが具体的にないため、同梱の機種専門リファレンス v1.0 §12.6を参照。過去handoffの数値を混ぜていない。出典は基準日2026-08-30であり、最新解析を保証しない。自動でWeb解析を書き換える機能は作らない。
3. EVの統合式は未提供。条件を満たす各ルートの最大の単独値を採用。表の下限行だけを使い、補間・上位激情恩恵の増額・モードの円換算をしない。非等価の女神スルーEVは欠損。ただし別の正常な独立ルートが成立すれば、それだけで判断できる。
4. 資金切れ確率・当選分布・残り必要投資、AT消化時間分布・閉店欠損のモデルが不足。架空の計算はしない。初版は「必要投資を照合済み」「AT/上位ルートまで取り切れ確認済み」を明示入力し、閉店時刻も記録。不明ならC→B。候補ラインやチェックを選ぶだけで現実の安全性が自動検証されるものではない。数値の自動リスク審査はTODO_NEEDS_SOURCE。
5. Cはattemptあたり追加確認1回。資金/閉店の確認はそのfieldに対応する1つの確認として扱う。画面を戻ってもC使用フラグを消さず、確認不能時はB。他の重要不明が残ればB。
6. EntrySnapshotはAを生成した時点でコピー。LIVE中の最新decisionとsnapshotを別に保持。保存APIはaddのみ、読み取りはdeepFreeze。migrationは外側のschemaVersionだけを補完し、raw/evidence/decisionを改変しない。
7. 女神1回狙い、スルー天井狙い、ATまでの狙いを区別して根拠消費を管理。AT終了後は直ちに離席せず、実機の一連状態を確認する指示。128実G引き戻しだけではAにしない。PUSHの5回先の示唆はEvidenceとして保管するが、将来の回数別金額評価・設定分布推定は未実装。
8. 営業日はAsia/Tokyoの日付（午前0時切替）。日付をまたぐactive LIVEは元の日と予算のまま復元。店舗ごとの営業日境界設定は将来拡張。
9. iPhone縦持ちを優先した。PlaywrightのEdgeモバイルviewportによる操作・横幅・オフラインを確認。実機iOS Safariのホーム画面インストール、長期ストレージ保持、バックグラウンド復帰は未検証。
