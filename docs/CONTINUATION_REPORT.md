# 継続実装：10機種・保存と当日確認

2026-10-08。公開先は https://gotsumorisan.github.io/hall-scan/ 。既存のからくり2記録とIndexedDB schema v2を維持し、履歴を削除せず拡張。

## 追加

- 9機種の独立したMachine Spec。各folderにschema・resolver・derived・PATROL・EV・Decision・LIVE・guideを配置。共通ハードルール、金額表と概算、失敗・当選のイベントを分離。
- PATROLで10機種を選び、機種固有の表示・履歴・証拠から共通SMART CHECKへ。通常CZと上位CZ、ボーナス間とループ間、周期モードと周期テーブル、あべしと実G等を混ぜない。
- MOREでJSONを保存・復元。8テーブルと当日確認情報をtransactionで保存。形式・保存版・投資合計・参照関係・snapshotのA根拠を検査。
- 異なる既存IDを上書きしない。同じ履歴は重複追加しない。初回起動の空の日だけは復元対象で置換可能。LIVE中は復元不可。失敗時は全体rollback。active LIVEは元の日・投資額で復元。
- TODAYで店舗候補の交換条件・閉店時刻・設置・出典・確認状況・メモを比較。DailyResearchOverrideとして当日のDailySessionに保存し、翌日に転記しない。店舗選択から自動Aにせず、Engineの基本ルールも変更しない。
- 初期報告の未公開記載を訂正。ローカルとGitHub履歴をmergeで統合し、force pushしない。

## 根拠

最上位はHALL_SCAN_CODEX_HANDOFF（2026-10-07）。現行handoffにない数値は同梱10機種リファレンスv2.0、海門・東京喰種・モンキーの専門資料を照合。旧アプリコードや過去の途中案は採用しない。ユーザー資料原文・参考画像は公開しない。

| 機種      | 基本ルート                                                                                                     |
| --------- | -------------------------------------------------------------------------------------------------------------- |
| 海門      | 媒体差を保守側へ丸め通常600/650G。短縮確認済み150/250G。個別金額は未算出                                       |
| 東京喰種  | 通常AT実G650/800Gの概算。resetは独立した初回CZまでの実G・CZ履歴0・reset confirmedが必要。液晶加算Gを流用しない |
| モンキーV | 現行v2.0の通常500/550G。専門資料の下限掲載行EV。確認済み短縮は専用条件                                         |
| リコリコ  | 固定Aラインを作らない指定。入力・相談・確認は可能。個別EV未提供なのでA/LIVE開始不可                            |
| 乙女5     | 通常AT間560/650Gの概算。周期・ストラップを円換算しない                                                         |
| VV2       | 通常900/1000G、reset confirmed500/600Gの実際の掲載金額                                                         |
| マギレコ  | 通常750/800pt、reset confirmed500/550ptの概算。穢れを円換算しない                                              |
| 転生2     | 通常900/975あべしの概算。天撃後の特殊状態と通常概算を混ぜない                                                  |
| 炎炎2     | 通常600/650G、reset confirmed450/500Gの概算。罠・ループの未提供EVを加算しない                                  |

概算資料の+2,000円級目安を満たす場合はsourceThresholdMetとして判定し、evYenはnull。「個別EV金額は未算出」を表示。実際の表と区別し、共通の資金・時間・当日解析条件も必要。

reset/短縮が確認済みなら専用条件を優先し、通常EVの高い数字だけを選ばない。reset possibleに専用EVを使わない。複数ルートは合算しない。天井到達後の値を通常の開始地点としない。通常最大までの距離と短縮確定の距離を同一の値として表示しない。
